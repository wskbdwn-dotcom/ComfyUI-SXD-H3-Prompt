# 单图结构化编辑扩写

新增节点 `SXDGemmaSpatialPlan` 和 `SXDSpatialPlanAssemble`，供 v9-live 的扩写阶段使用。现有 `SXDGemmaImageTask` 的 `prompt` 与 `anatomy` 任务继续沿用原接口。

## 更新与工作流

在已安装的本仓库目录执行 `git pull --ff-only origin main`，重启 ComfyUI 并刷新浏览器，然后导入 [v9-live 结构化副本](../workflows/qwen/image2image_qwen2.1-gemma-v9-live-structured.json)。只拉插件不会自动替换已打开的旧工作流。

工作流依赖原 v9-live 的 Qwen 编码、生图、EasyUse、Set/Get、URL 图片读取等现有节点，不是一个仅依赖本插件的新环境安装示例。

仓库中的副本不含测试人物图片地址或旧请求示例。节点 1109 填单张参考图 URL，节点 1200 填原始编辑要求，节点 1201 可填已核验事实或留空。默认主模型和 mmproj 使用原文件名作为相对路径；如运行环境目录不同，替换为原配置中实际可用的路径。其余采样配置沿用本次 v9-live 基线。

流程：原始要求、单张参考图、可选的已核验事实 → 一次 Gemma 生成结构化规划 → 字段与引用检查 → 无模型调用的中文组装 → `{"prompt":"…"}` → 原有 JSON 提取与生图流程。

新增人物的基础姿态必须选择 `standing / seated / kneeling / crouching / lying / other`。原图人物支撑关系不明确时可选择 `visible_only`，并写明实际可见姿态。该枚举由组装器转为中文，不再依赖自由成文时是否漏写姿态。`other`、`visible_only` 和 `kneeling` 必须有具体描述。程序不会用默认站姿自动补齐缺项。

结构化字段说明由插件内置的 `spatial_plan_rules.txt` 提供。旧的长扩写规则不接入这个新节点；v9 副本的原规则输入区域改为“已核验图像事实”，可以留空。换参考图时应重新确认或清空这些事实。

## 节点输入和输出

规划节点输入：原模型配置、原始要求、可选核验事实、原种子和图片。只接受合计一张图片。模型加载、缓存、思考处理、重复检测、释放行为与现有节点共用。

规划节点输出 0 是通过结构检查的 `plan_json`，输出 1 是用于实时查看的 `raw_output`，输出 2 是原始用户要求。后两者不作为生图提示词。`raw_output` 仍可直接连接 `H3PromptLiveDisplay`。

组装节点输入规划 JSON 和原始用户要求，输出 0 是唯一字段为 `prompt` 的 JSON，输出 1 是同一段纯文本。它没有模型调用。缺项、非法姿态、错误引用和已识别的文字归属冲突会报错，后续生图不会收到由默认值拼出的指令。没有自动重试。

## 检查能做什么

- 检查人物位置、基础姿态、躯干朝向和动作字段是否存在。
- 检查新增人物是否选择了具体基础姿态，人物和物品编号是否唯一，接触端点与物品主人是否存在。
- 检查空间任务的镜头方向、高度、取景和遮挡说明是否存在；对“与坐姿持平”“侧面”“完整清晰展示”等部分笼统写法作保守拦截。
- 对原请求中“腰间＋相同物品名”“手持＋相同物品名”等明确文字进行少量确定性归属检查。只覆盖实际匹配的文字，不等于理解任意同义说法。
- 将姿态枚举和物品挂载方式转成中文，生成最终单行 JSON。

完整 JSON 外如果只有一层代码块包装，入口会移除包装后继续校验；不会从带解释或多个候选对象的正文里猜选 JSON。不同人物 ID 使用同一显示称呼时，会给称呼加序号以便区分，ID、物品归属、姿态与接触引用保持原样。腹部高度也属于有效的身体高度参照。这些格式与显示归一化不会跳过姿态、引用或具体观察侧的检查。

## 检查不能证明什么

这不是受 JSON Schema 约束的底层解码。现有推理链路没有新增 grammar 或 response_format；由模型生成 JSON，程序在生成后验证。不符合结构时会停住，而不是保证每次一次成功。

字段非空不能证明字段内容正确。程序无法仅凭文字确认参考图中的站坐姿、身体可达性、实际遮挡、动作语义是否忠实，或模型是否遗漏了某个未被单独编码的用户要求。自由文本字段也可能与枚举矛盾。已核验事实目前供模型使用，不是自动视觉真值判断器。

因此仍需以实际参考图和原始要求验收。与旧版相比，此方案把一些可机械检查的遗漏变为明确错误，不能代替视觉和语义评估。
